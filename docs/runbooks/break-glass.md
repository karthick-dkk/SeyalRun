# Runbook: Break-Glass Access
**Severity:** P1
**Owner:** karthick (karthidkk123@gmail.com)
**Last tested:** Never (TEST THIS IN LAB BEFORE RELYING ON IT)

## When to Use
Use this procedure when:
- FreeIPA LDAP is down → JumpServer users cannot log in
- JumpServer is up but authentication is broken
- You are locked out of all normal admin access

## Symptoms
- JumpServer login page shows "LDAP server unreachable" or times out
- Regular admin credentials rejected
- All sidecar services show LDAP-related errors in logs

## Prerequisites
- SSH key access to 192.168.64.2 (if you set up SSH keys before this happened)
- OR physical/console access to the VM

## Procedure

### Step 1: Access Server 1 via SSH key
```bash
ssh test@192.168.64.2
# If SSH key auth was set up and password auth disabled — this is your only way in
# If locked out completely, use your VM console (UTM / Parallels)
```

### Step 2: Retrieve current DB credentials
```bash
sudo cat /opt/jumpserver/config/config.txt | grep -E "^(DB_|REDIS_|SECRET_)"
# Note: DB_ENGINE=postgresql, DB_HOST=postgresql (Docker container name)
```

### Step 3a: Reset JumpServer local admin password (fast — preferred)
```bash
# Connect to the running JumpServer core container
sudo docker exec -it jms_core bash

# Inside container — create or reset local admin
cd /opt/jumpserver
python manage.py changepassword admin
# OR create a new superuser if admin doesn't exist:
python manage.py createsuperuser --username breakglass --email admin@lab.local
exit
```

### Step 3b: If jms_core is down — direct DB access
```bash
# Connect to PostgreSQL container
sudo docker exec -it jms_postgresql psql -U postgres -d jumpserver

-- Find admin user
SELECT id, username, is_superuser, is_active FROM users_user WHERE is_superuser = true;

-- Temporarily enable local (non-LDAP) auth for the admin user
UPDATE users_user SET source='local' WHERE username='admin';
-- OR create emergency user (hash generated by Django)
\q
```

### Step 4: Log into JumpServer web UI
```
http://192.168.64.2
Username: admin (or breakglass)
Password: whatever you set in Step 3
```

### Step 5: Disable LDAP temporarily
```
JumpServer UI → System Settings → Authentication → LDAP
Toggle: Disable LDAP
```
This allows all local users to log in while you fix FreeIPA.

### Step 6: Fix the underlying problem
- Check FreeIPA container: `sudo docker ps | grep freeipa`
- Restart FreeIPA: `sudo docker restart freeipa`
- Check FreeIPA logs: `sudo docker logs freeipa --tail=100`

### Verification
- Log in with a regular LDAP user after re-enabling LDAP
- `ldapsearch -H ldaps://192.168.64.2:636 -x -b "dc=lab,dc=pravesh,dc=local"` returns results

### Rollback
- Re-enable LDAP in JumpServer after FreeIPA is restored
- Remove the breakglass local user

### Post-incident
- Document what caused FreeIPA to go down in `docs/incidents/YYYY-MM-DD.md`
- Add monitoring alert so this is detected automatically next time
- Test this runbook quarterly
